# Dataset Guide (Phase 4) — verified public options + self-collection plan

**Rule: we do not pretend a dataset exists.** Last verified by live web search
on 2026-08-31.

## 1. What actually exists publicly (verified)

| Dataset | Size | Labels | Verdict |
|---|---|---|---|
| Roboflow Universe — "Onion detection" (KryoTech) | **261 images** | `rotten`, `sprout` (bounding boxes) | ✅ Useful starting point for rot/sprout detection; too small & incomplete for full grading. Public-domain license. |
| Roboflow Universe — "onion disease" (A. Kadiri) | **53 images** | onion (disease) | ⚠️ Tiny; marginal value |
| Roboflow Universe — "Onion Leaf Disease" | 504 images | 7 leaf diseases | ❌ **Leaves, not bulbs** — wrong target for bulb quality |

**Conclusion:** there is **no adequate public dataset for onion BULB quality
grading** (healthy/rotten/damaged/sprouted/undersized/discolored/deformed).
Plan: seed with the 261-image set if useful, and **collect our own** — which is
also the strongest demo story for SIH ("trained on field data from actual
procurement conditions").

## 2. Self-collection procedure

* **Classes (7):** healthy, rotten, damaged, sprouted, undersized, discolored, deformed
* **Target:** ≥ 150–300 usable photos per class (the baseline model needs
  ~20+ minimum; more = better metrics). Aim for 5–8 onion varieties
  (red/pink/white), 3+ backgrounds (jute sack, table, floor), 3 lighting
  conditions (sun, shade, indoor), 2–3 different phones.
* **Protocol per photo:** one onion, whole onion visible, 30–60 cm distance,
  plain contrasting background. Log date/place/variety/camera in
  `datasets/onion_defects/NOTES.md`.
* **Honesty rule:** label only what is VISIBLE ("rotten" = visible black/soft
  patch, not guessed internal rot).

## 3. Folder structure

```
raw_photos/                 # originals, never modified
  healthy/  rotten/  damaged/  sprouted/  undersized/  discolored/  deformed/

datasets/onion_defects/     # generated by scripts/build_dataset.py
  classes/
    train/{class}/...       # 70% + augmented copies (×7)
    val/{class}/...         # 15%, NEVER augmented
    test/{class}/...        # 15%, NEVER augmented — the final honesty check
  NOTES.md                  # provenance log
```

## 4. Tooling (all free)

* **Labeling:** for classification, the folder name IS the label. For defect
  *bounding boxes* (needed for the later YOLO model), annotate in **Roboflow
  (free tier)**, **CVAT**, or **Label Studio**; export YOLO `.txt` format.
* **Splitting + augmentation:** `python scripts/build_dataset.py --raw raw_photos`
  (brightness/contrast/gamma, hue shift, rotate/scale/flip, blur, noise —
  simulating lighting/shadow/dust/camera variation).
* **Training:** `python scripts/train_baseline.py` locally, or the same code in
  a free **Google Colab** notebook (upload the `datasets/` folder).
* **Advanced model (Phase 5+):** fine-tune YOLOv8n (detection) / MobileNetV3
  (classification) in Colab's free GPU. Export `best.pt` → `models/`.

## 5. Annotation formats

* Classification: class-folder layout (no per-image files needed).
* Detection: YOLO `.txt` per image — `class_id cx cy w h` (normalised 0–1) +
  `dataset.yaml` listing class names.

## 6. Splits & honesty

* 70/15/15 stratified, seed 42, **captured on different days** for test if
  possible so the test set is genuinely unseen.
* Metrics are reported **from the test set only**, and always quoted as
  "measured on our N-image test set", never as general accuracy.
